# 혼페이지 주간 점검

한 주에 한 번, 사이트를 **재서** 상태를 보고하고 다음에 할 일을 **고를 수 있게** 내놓는다.
결과물은 둘이다.

1. **고친 버그** — 분명한 것만, 하나에 PR 하나씩. 전후 값을 잰다.
2. **제안서** — `report-template.html` 로 만든 한 장짜리 페이지(Artifact).
   사람이 체크박스로 고르면 "주간 점검(M/D) 제안 중 … 진행해줘" 한 줄이 만들어진다.
   생김새는 `example-2026-09-30.html` 이 기준이다 — 사용자가 "이 모양이 맘에 든다" 고 한 판.

말투 · 커밋 · PR 규칙은 저장소 `CLAUDE.md` 를 그대로 따른다.

## 순서

### 1. 맞추기

```
git fetch origin main -q && git checkout -qB claude/claude-md-docs-mvszjm origin/main
```

`history.md` 맨 아래 항목을 읽는다 — 지난주에 무엇을 골랐고 무엇을 안 골랐는지,
무엇을 보류하기로 했는지. **안 고른 제안을 이번 주에 또 똑같이 내지 않는다.**
다시 낼 거면 무엇이 달라졌는지(새로 잰 값)를 붙인다.

### 2. 회귀 시험 전부

```
/opt/node22/bin/node tools/checks/run.mjs          # 전체 26벌, 15분쯤
```

- 판정은 종료 코드 0 **과** 끝줄 "전부 통과" 둘 다. ❌ 만 찾지 않는다.
- 하나라도 깨지면 먼저 `git stash` / `git worktree` 로 지난 판에서 돌려
  원래 깨지던 것인지, 이번 주 변경이 깬 것인지 가른다. **기대값을 고쳐 통과시키지 않는다.**
- `weekly` · `calholiday` 는 오늘 날짜에 따라 결과가 바뀐다 — 깨지면 날짜부터 의심한다.

### 3. 점검 도구

```
/opt/node22/bin/node tools/checks/audit.mjs        # tap-contrast a11y monkey dates weight
```

판정 없이 숫자만 낸다. 지난주 값과 견줘서 **늘어난 것**을 본다.
기준: 누를 곳 44px · 글씨 명암비 4.5 · 선/도형 3.0 · 글씨 크기 12/14/16/18/20/24 ·
폰 한 화면 390×844 (넓은 폰 414 · 430, 좁은 폰 320 도 본다).

### 4. 데이터 신선도

| 무엇 | 어디 | 볼 것 |
|---|---|---|
| 대회 일정 | `js/events.js` | 마지막 대회 날짜가 지났나 — 지났으면 "다음 대회 없음" 이 화면에 어떻게 보이나 |
| 공휴일 | `js/events.js` 공휴일 목록 | 목록 끝 해. 2028년 것은 2027년 가을까지 넣는다 |
| 선수 기록 | `js/roster.js` | 몇 월까지의 기록인가 |
| 정기 운동 | `RECURRING_EVENTS` | 시간 · 장소 · 참불 마감이 실제와 같은가(모르면 묻는다) |

### 5. 새 버그 찾기

지난 점검 뒤 들어온 PR 부터 본다(`git log <지난주 끝 커밋>..origin/main`).
새로 바뀐 곳이 새 버그가 제일 잘 나는 곳이다. 직접 눌러 보고, 받은 파일(엑셀 · 이미지)을
열어 숫자를 맞대 본다.

**눈으로 본 것은 근거가 아니다.** 찾은 것마다 잰 값(px · 명암비 · 개수 · 오류 문구)을 남긴다.
잴 때 자주 틀린 것들:

- `page.goto` 로 해시만 바꾸면 새로고침이 안 된다 — 테마가 안 바뀐 채 잰다.
- 반투명 배경은 밑 색과 합성해서 명암비를 잰다.
- `disabled` 버튼은 명암비 기준 밖이다.
- `getBoundingClientRect` 는 `clip-path` 를 모른다 — 잘림은 픽셀로 잰다.
- 누를 곳 크기는 화면 안으로 굴려 놓고 잰다.
- h1 32px 은 일부러다(`css/style.css:89`). 글씨 사다리 위반으로 잡지 않는다.

### 6. 분명한 버그는 고친다

- **하나에 PR 하나.** 커밋 · PR 본문에 무엇을 왜 고쳤고 무엇을 쟀는지, 숫자 그대로.
- 고친 것마다 `tools/checks/suites/` 에 시험을 더하고 `run.mjs` 목록에 한 줄 설명과 넣는다.
  **고치기 전 코드에서 그 시험이 깨지는 것까지** 확인한다.
- PR 자동 검사(회귀 시험 빠른 묶음)가 초록인지 보고 병합 → 배포 확인 → 브랜치 다시 맞추기.
- **동작이나 생김새가 바뀌는 것은 고치지 않는다.** 그건 제안서로 간다.
  "니맘대로 바꾸지 말고" — 사용자가 분명히 말한 선이다.
- 애매하면 버그가 아니라 제안이다.

### 7. 제안서 만들기

`report-template.html` 을 복사해 채운다. 칸마다 안내 주석이 있다 — 채운 뒤 주석은 지운다.

**제목** `혼페이지 주간 점검 M·D` · 아이콘 `checklist` · 저장 키 `hon-weekly-MMDD-picked`
(주마다 바꿔야 지난주 고른 것이 딸려 오지 않는다).

위에서 아래로:

1. **머리** — 날짜, rev 지난주 → 이번 주, 숫자 넷(고친 버그 · 시험 벌수 · 눌러 본 버튼과 오류 · 제안 수).
2. **고친 것** — PR 하나에 칸 하나. 전후 값을 `<s>전</s> → <b>후</b>` 로.
3. **멀쩡한 것** — 잰 것과 값. "문제없음" 도 잰 값으로 말한다.
4. **고를 것** — 세 묶음.

   | 머리글자 | 묶음 | 무엇 |
   |---|---|---|
   | **S** | 자동화 · 도구 | 점검 · 시험 · 배포를 사람 손 덜 가게 |
   | **B** | 남은 문제 | 재서 찾았지만 고치면 생김새가 바뀌거나 판단이 필요한 것 |
   | **F** | 기능 아이디어 | 동호회 사람이 실제로 쓰는 순간(참불 · 팀 짜기 · 기록 · 밴드 올리기)에서 출발 |
   | **D** | 디자인 제안 | 아래 5번 |

   항목마다 태그 `hi`(효과 큼) · `mid` · `lo`, 그리고 **왜 · 무엇을 · 무엇이 달라지나**.
   잰 값이 있으면 넣고, 아직 안 잰 어림값은 "(어림 — 만들고 잴게요)" 라고 밝힌다.
5. **디자인 제안** — 이번 주 주제 하나(예: 첫 화면, 기록 화면, 넓은 폰).
   - 왼쪽 **지금**: 반드시 실제 화면. `now-shot.mjs` 로 찍는다.
     ```
     /opt/node22/bin/node .claude/skills/weekly-check/now-shot.mjs "#/" dark 2026-10-07T10:00 > 지금.txt
     ```
     (390×844 JPEG, 30~40KB. 시각을 주면 D-day · 오늘 칸이 그날 기준으로 찍힌다.)
     잰 값은 `.ruler` 로 선을 긋는다 — `top` 은 `px / 844 × 100 %`.
   - 오른쪽 **제안**: `.mock` 조각(`.mock-top` `.mock-body` `.week` `.grid2` `.last` `.tabbar`)
     으로 그린 시안. 없는 모양은 같은 결로 더한다.
   - 그 아래 D 항목들을 체크박스로.
6. **알아 둘 것** — 보류한 것, 일부러 그런 것, 다음 주에 볼 것.
7. **추천 순서** — 무엇부터 왜. 서로 기대는 것(예: D2 · D3 는 한 PR)을 적는다.
8. **고른 것 줄** — 체크하면 채워지는 복사 칸. 건드릴 것 없음.

만든 뒤 Playwright 로 390px 에서 열어 가로 스크롤이 없는지, 체크 → 복사 칸 글이 맞는지 본다.
그 다음 Artifact 로 올린다(새 파일 경로 = 새 주소. 주마다 새 페이지).

### 8. 보고

채팅에는 짧게: 고친 PR 들, 시험 결과 한 줄, 제안서 링크, 고르는 법
("체크하고 아래 줄을 복사해서 붙여 줘"). 그리고 Q1~Q3.

`history.md` 맨 아래에 이번 주 항목을 더한다(rev, PR, 제안 번호들). 사용자가 고르면
고른 것 · 안 고른 것을 채운다. 이 파일도 PR 로 올린다.

## 이미 정해진 것 (다시 제안하지 않는다)

- 달력 칸 크기 — 보류(사용자 결정).
- 전술 편집기의 × 버튼 — 일부러 그 자리.
- 선수 숫자표(roster 의 기록 표) — 제안에서 뺌.
- 모듈을 처음에 다 받는 것 — 오프라인 화면 이동 때문에 일부러.
- 서비스 워커 — 없음. 넣자는 제안은 오프라인 새로고침 문제를 잰 뒤에만.

## 파일

| 파일 | 무엇 |
|---|---|
| `report-template.html` | 제안서 틀. `{{…}}` 와 안내 주석 |
| `example-2026-09-30.html` | 처음 올린 판(모양 기준). 칸을 어떻게 채우는지 볼 때 |
| `now-shot.mjs` | "지금" 화면을 data URI 로 |
| `history.md` | 주마다 한 항목 — rev, 고친 것, 제안, 고른 것 |
