# 기록지 자동화(OMR) 검토 기록

> **상태: 검토 완료, 제작 대기.** 아직 아무것도 만들지 않았다.
> 2026-08-18 검토. 팀원 논의 후 제작 요청이 오면 이 문서에서 이어서 시작한다.

수기 기록지를 마킹(OMR) 방식으로 바꾸고, 사진을 올리면 엑셀이 나오게 하려는 계획.
지금은 경기 후 사람이 종이를 보고 엑셀에 손으로 옮겨 적고 있다.

이 문서는 **결정된 것 / 실제로 재본 숫자 / 아직 안 정한 것**을 나눠서 적는다.
숫자는 전부 팀 기록 엑셀(66시트)과 실제 측정에서 나온 것이고, 추측은 추측이라고 적었다.

## 1. 결론부터

| 항목 | 결론 |
|---|---|
| 홈페이지 한 페이지로 가능한가 | **가능** |
| 서버(서버리스 함수) 필요한가 | **불필요.** 전부 브라우저에서 처리 |
| AI API 비용 | **0원.** 양식을 우리가 만드니 버블 좌표를 아는 상태 → 단순 명암 판독 |
| OpenCV 필요한가 | **불필요.** 기준 마크 4개 → 기울기 보정 → 정해진 좌표 샘플링이면 끝 |
| 엑셀 이어붙이기 안전한가 | **안전 확인됨** (3절) |
| 종이 폭이 모자라지 않나 | **모자라지 않음.** 현행 종이가 이미 해결해 둠 |

서버가 필요 없는 이유: 이 기능은 "파일 넣고 → 변환 → 파일 받기"가 전부고 **저장이 없다.**
그래서 GitHub Pages(정적 호스팅)에 그대로 올려도 된다.
부수 효과로 사진이 인터넷에 안 올라가고, 인터넷이 끊겨도 동작한다(이미 PWA).

## 2. 기존 엑셀 파일 구조

`TalkFile_혼스탯.xlsx` 기준. **66시트 / 2024-04 ~ 2026-06 / 669KB.**

하루가 시트 한 장이고, 그 안에 **경기 블록이 1~6개** 들어간다.
3파전이면 6블록 = 혼A·혼B·혼C가 각 2경기 (실제 3경기를 양쪽 시점에서 기록).

블록 하나는 **17줄 간격**으로 반복된다:

```
혼 A                                   ← B1: 팀
1경기                                   ← B2
Team   1Q   2Q   3Q   4Q  Total        ← 헤더
혼A    12    9   10   10  =SUM(B4:K4)  ← 쿼터별 "증가분" (누적 아님!)
혼B     7   10    8   10  =SUM(B5:K5)
Play   14,10,24,35,12 | ...            ← 쿼터별 코트 위 5명 등번호
(빈 줄)
No Player MIN 2PM 2PA 2P% ... 비고     ← B~X열
14 홍재현  32   2   4  =IFERROR(E9/F9,0) ...
...
TEAM   =SUM(...)
```

- 컬럼: `B=No, C=Player, D=MIN, E~W=스탯, X=비고`
- `MIN = 출전 쿼터 수 × 8분` (8/16/24/32에 몰려 있음, 1,463건 중 1,330건)
- `Play` 줄은 쿼터마다 코트 위 5명의 등번호. **`①②③④` 동그라미에서만 나온다.**
- 시트명 규칙: `YYMMDD_경기유형` (예: `260628_자체3파전`)

### ⚠️ 서식이 5종류로 섞여 있다

| 형태 | 시트 수 |
|---|---|
| 현행 (`B=No, C=Player`, 2PM/2PA 분리) | **43** |
| 구형 (`B=Player`, No 컬럼 없음) | 23 |

→ **새로 만드는 시트만 현행 형식으로 쓰면 되고, 옛 시트는 건드릴 일이 없다.**

## 3. 엑셀 이어붙이기 — 안전 확인됨

"기존 누적 파일에 새 시트를 추가해서 돌려준다"가 서식을 깨뜨릴까 봐 걱정했는데,
**실제 파일로 읽고 다시 저장해서 대조해 봤다.**

| 검사 | 결과 |
|---|---|
| 셀 111,925개 값 비교 | 차이 **9개** (전부 `빈 문자열 → 빈 칸`, 의미 없음) |
| 서식 (채움·테두리·굵기·표시형식·정렬) | 차이 **0개** |
| 병합셀 4,937개 | 전부 유지 |
| 열 너비 · 수식 · 시트 66개 | 전부 유지 |

안전한 이유: 이 파일에 **차트·이미지·조건부서식·데이터유효성·매크로가 하나도 없다.**
순수한 표 + 수식 + 테두리라 왕복이 무사하다.

> ⚠️ 단, 이건 파이썬 라이브러리(openpyxl)로 시험한 결과다.
> **브라우저용 라이브러리로 한 번 더 확인해야 한다** — 제작 착수 시 첫 번째 할 일.

### 기존 파일에서 발견한 사소한 흠 (새로 만들 때 안 물려받으면 된다)

- `K17='=SUM(K7:K16)'` — 데이터는 9~16행인데 7행부터 더한다. 빈 칸이라 결과는 맞지만 범위가 어긋나 있다.
- `L4='=SUM(B4:K4)'` — 팀 이름 칸(B4)까지 포함. 텍스트는 무시되니 결과는 맞다.

## 4. 현행 수기 기록지 분석

**이미 절반은 OMR이다.** 2점/3점/자유투 칸에 `2 2 2 2 2…`가 미리 인쇄돼 있고,
시도 순서대로 표시하는 방식이다.

| 지금 방식 | OMR 적합성 |
|---|---|
| 슛: 한 시도에 칸 하나, **성공 ○ / 실패 ✗** | ❌ ○와 ✗는 칠해진 양이 비슷해 명암으로 구분 불가 |
| 카운트 스탯: `一 → T → F → 正` 획으로 세기 | ❌ 획 모양을 읽어야 해서 불가 |
| 출전 쿼터: `①②③④` 동그라미 | ✅ 그대로 OMR 가능 |
| 쿼터 점수: **누적**으로 기입 (14 → 20 → 23 → 39) | 엑셀은 **증가분**(14/6/3/17). 지금은 사람이 빼서 옮긴다 |

→ 슛의 ○/✗를 **성공 줄 / 실패 줄로 분리**하는 것이 새 양식의 핵심.
→ 쿼터 점수는 **종이는 누적 그대로 두고 프로그램이 빼면 된다** (현장에선 누적이 편하다).

> 실제로 6/16 1경기에서 종이 4쿼터 `39`, 엑셀 `40`으로 1점이 안 맞았다.
> 사진 판독 오류일 수도 있지만, 자동화하면 사라지는 종류의 오차다.

## 5. 새 양식(OMR 가안) 검토 결과

### 🔴 반드시 되살려야 할 것: 쿼터 칸 `①②③④`

가안에서 빠져 있는데, 이게 없으면 **MIN도 Play 줄도 만들 수 없다.**
선수당 버블 4개면 해결된다. (단, 8절의 4색 방식을 쓰면 색이 대신하므로 불필요해진다.)

### 🟡 버블 개수 재배치 — 실측 근거

66시트에서 **선수-경기 기록 1,681건**을 뽑아 실제 최댓값을 확인했다.

| 항목 | 실제 최대 | 99% | 95% | 평균 | 가안 | 권장 |
|---|---|---|---|---|---|---|
| 2점 시도 | 24 | 16 | 12 | 5.2 | 20 | **20** ✅ |
| 3점 시도 | 15 | 11 | 7 | 2.2 | 10 | **12** ⚠️ 부족 |
| 자유투 | 14 | 8 | 5 | 1.0 | 10 | **10** ✅ |
| 리바운드 | 20 | 14 | 10 | 4.1 | 15 | **15** ✅ |
| 어시스트 | 9 | 7 | 5 | 1.8 | 15 | **10** 🔻 과함 |
| 스틸 | 7 | 4 | 3 | 0.8 | 15 | **8** 🔻 과함 |
| 블락 | 9 | 3 | 1 | 0.2 | 15 | **8** 🔻 과함 |

재배치하면 선수당 **160개 → 145개** (쿼터 4개를 더하고도 줄어든다).
**남는 자리로 버블을 키울 것** — 가안은 지름 3mm 안팎으로 보이는데 경기 중에 칠하기엔 작다.

### 🟢 선수 줄 수 — 두 종류로 뽑는 게 낫다

경기당 인원: **6~8명이 84%**, 최대 11명(대회).
→ **자체전용 8줄(버블 크게) / 대회용 12줄** 두 가지.

### 🟢 손글씨 칸은 전부 없앨 수 있다

| 지금 손글씨 | 없애는 방법 |
|---|---|
| 선수 이름 · NO. | 팀 편성에서 **미리 인쇄** |
| 날짜 / GAME No. / 상대팀 | **미리 인쇄** |
| 쿼터 점수 | 십의자리·일의자리 **버블** (0~99) — 자리를 먹지만 사람 손이 완전히 빠짐 |
| 비고 | 유일하게 남김 → **검수 화면에서 타이핑** |

## 6. 손글씨는 읽을 수 없다 (그래서 없애는 것)

| | 브라우저만으로 |
|---|---|
| 마킹된 버블 | ✅ 거의 확실 |
| 색 구분 (검정/빨강) | ✅ 잘 됨 |
| 인쇄체 숫자 | 🔺 되긴 하나 오차 있음 |
| **손글씨 숫자** | ❌ 실용 수준 아님 |
| **손글씨 한글 이름** | ❌ 전혀 안 됨 |

브라우저에서 도는 무료 문자인식(tesseract.js)은 **인쇄 활자용**이라 손글씨는 거의 못 읽는다.
유료 AI API를 쓰면 읽히지만, 그건 애초에 피하려던 방향이다.

## 7. 색 인식 — 된다

사진은 색 정보를 그대로 담고 있으므로, 칸마다 "얼마나 진한가"에 더해 "무슨 색인가"를 재면 된다.

| 상태 | 밝기 | 색 선명도 |
|---|---|---|
| 빈 칸 | 밝음 | 없음 |
| 검정 | 어두움 | **없음** |
| 빨강 | 중간 | **강함** |

검정("색 없는 어두움")과 빨강("색이 뚜렷한 중간 밝기")은 멀리 떨어져 있어 헷갈리지 않는다.
○/✗ 구분보다 훨씬 쉽다.

### 필수 조건: 기록지에 색 견본을 인쇄할 것

체육관 조명 색온도에 따라 폰 카메라가 흰 종이를 누렇게/푸르스름하게 찍는다.
→ 귀퉁이에 **흰색·검정·빨강 견본 사각형**을 인쇄해두고, 사진마다 견본으로 먼저 맞춘 뒤 판독한다.
기준 마크(기울기 보정용)와 같은 자리에 넣으면 된다.

### 용도 ①: 취소 — 조건부

**칸 안에 덧칠하면 안 된다.** 검정 위에 빨강을 덧칠하면 검정이 이겨서 그냥 시커먼 칸이 된다.
→ **그 칸을 가로지르는 빨간 줄**로 표시. 판독은 "이 칸 주변에 빨간색이 있나?"만 보면 되므로 모양 인식이 아니다.

> 취소가 꼭 필요하진 않다. 검수 화면에서 고칠 수 있다.
> 다만 현장에서 "잘못 칠했다"를 남겨둘 수 있으면 나중에 기억을 더듬을 일이 없다.

### 용도 ②: 쿼터 구분 — 강력 추천

**4색 볼펜 하나로 1Q 검정 / 2Q 빨강 / 3Q 파랑 / 4Q 초록.**

얻는 것:
1. **`①②③④` 칸이 필요 없어진다** — 색만 봐도 출전 쿼터를 알 수 있다 → MIN·Play 자동
2. **쿼터별 개인 스탯**이 공짜로 생긴다 (지금 엑셀에 없는 정보)
3. **오류 검사가 쿼터 단위로 촘촘해진다** — "3쿼터가 4점 안 맞는다"까지 좁혀준다

주의:
- **파랑·초록은 빨강보다 어렵다.** 볼펜 잉크가 옅어 색이 덜 뚜렷하다. 견본 패치로 되지만 여유가 적다.
- 기록자가 색 바꾸는 걸 잊으면 그 쿼터 전체가 앞 쿼터로 붙는다 → 위 3번 검사로 잡힌다.

### 단계적 도입 (각 단계가 앞 단계를 안 깨뜨린다)

| 단계 | 색 | 얻는 것 | 위험 |
|---|---|---|---|
| 1 | 검정만 | 원래 하려던 것 전부 | 없음 |
| 2 | + 빨강 (취소) | 현장 수정 | 낮음 |
| 3 | 4색 (쿼터) | 쿼터별 스탯 + 쿼터 칸 제거 | 중간 |

**4색을 전제로 설계하되 1단계로 시작한다.** 종이는 그대로 두고 판독 규칙만 늘어난다.

## 8. 검수 화면은 필수

체육관 조명·그림자·구겨진 종이·폰 각도 때문에 OMR은 100%가 안 나온다.

→ 업로드 후 **인식 결과를 표로 전부 보여주고, 애매한 칸은 빨갛게 표시해 손으로 고친 뒤 다운로드.**
이게 있으면 최악의 경우도 "지금처럼 손으로 입력"하는 수준이지, 데이터가 조용히 틀어지지 않는다.

### 넣을 검사 목록 (과거 66시트로 미리 돌려본 결과)

| 검사 | 과거 데이터에서 |
|---|---|
| 1. 팀 쿼터 점수 합 = 개인 득점 합 | **205블록 중 18건(9%)이 불일치** (최대 43점 차) |
| 2. **교차 검증** — 3파전은 같은 경기가 두 시점으로 기록됨 | `260628` 3경기 전부 양쪽 점수 일치. 한쪽을 잘못 읽으면 바로 걸린다 |
| 3. 쿼터별 대조 (4색 도입 시) | 오류를 쿼터 단위로 좁혀줌 |
| 4. Play 줄이 쿼터마다 5명인가 | **36건이 5명 아님** (6~8명) |
| 5. 출전 쿼터 수 × 8분 = MIN | **1,463건 중 133건이 8의 배수 아님** (대회 때 쿼터 시간이 다른 듯 → 경고만) |
| 6. 성공 ≤ 시도, 같은 선수 두 팀 동시 등장 | — |

2번이 특히 강력하다. 이 팀의 기록 방식(3파전을 양쪽 시점에서 기록)에서만 가능한 검사다.

## 9. 전체 흐름

```
1. 팀 편성에서 팀을 짠다              ← 이미 있는 기능 (2팀/3팀, TEAM_LETTERS = A/B/C)
2. 이미지 내보내기로 팀 공유           ← 이미 있는 기능
3. 인쇄용 기록지 PDF 출력  ★신규       ← 이름·날짜·대진이 미리 채워진 6장
4. 현장에서 수기 작성
5. 사진 + (선택) 누적 엑셀 업로드  ★신규
6. 검수 → 업데이트된 엑셀 다운로드  ★신규
```

### 3번은 반드시 **PDF**로 (엑셀 ❌)

| | 엑셀 | 이미지(PNG) | **PDF** |
|---|---|---|---|
| 버블 위치 고정 | ❌ 프린터·설정 따라 변함 | 🔺 배율 의존 | ✅ mm 단위 고정 |
| 기준 마크·색 견본 배치 | ❌ | 🔺 | ✅ |

**OMR은 좌표가 생명이다.** 지금까지 엑셀로 뽑아 써도 문제없던 건 사람이 읽었기 때문이다.
인쇄 시 "실제 크기(100%)" 안내가 필요하지만, 기준 마크 4개가 있으면 배율이 틀려도 보정된다.

**다운로드(6번)는 엑셀이 맞다** — 받아서 직접 편집해야 하므로.

### 팀 편성과 이미 맞아떨어지는 것

`js/team-shuffle.js`가 이미 `260824_자체3파전` 형식 라벨을 만든다.
**엑셀 시트명 규칙(`YYMMDD_경기유형`)과 똑같다.** 팀 짜는 순간부터 엑셀 시트 이름까지 한 줄로 이어진다.

### 노쇼·게스트 처리

팀 편성은 경기 전에 하는데 사람이 안 오거나 게스트가 온다.
→ 팀마다 **빈 줄 1~2개**를 같이 인쇄하고, 검수 화면에서 줄↔선수를 바꿀 수 있게 한다.

## 10. 결과 엑셀에 판독 메모를 남길 것

사이트는 서버에 아무것도 저장하지 않는다. 나중에 "이 파일 이상해요"라고 해도 꺼내볼 데가 없다.
→ 새로 만드는 시트 구석에 한 줄을 남긴다:

```
2026-08-24 · 사이트 버전 abc1234 · 기록지 6장 · 자동판독 후 3칸 수동수정
```

어느 버전이 만든 파일인지가 파일에 붙어 다녀서 원인 추적이 쉬워진다. 비용은 거의 0.

**원본 사진은 폰에서 지우지 말 것.** 사이트가 안 갖고 있으므로 그게 유일한 원본이다.
